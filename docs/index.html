Sync target

Your triage decisions are written to a JSON file in a GitHub repo you own. That file is also how the app works across devices.

Access token

Leave blank to keep the saved token. Testing a valid token saves it.

How to create the token
  1. Open github.com/settings/personal-access-tokens/new
  2. Token name: anything you'll recognise later
  3. Expiration: the longest you're comfortable with (1 year max)
  4. Repository access: Only select repositories → the repo named above
  5. Permissions: Repository permissions → Contents → Read and write
    That is the only permission needed. Not repo — that's the old classic-token scope, and it grants far more.
  6. Generate, copy the github_pat_… string, paste it above, press Test token

Where the token lives: in this browser's localStorage, in plain text. Anyone with access to this browser profile can read it. Use a fine-grained token scoped to this one repository with Contents-only permission, so that is the whole blast radius, and revoke it on the GitHub token page if a device is lost. Clearing site data or reinstalling the app wipes it and you paste it again.

Tokens expire. When yours does, sync fails with a 401 and you make a new one — nothing is lost, your triage stays queued locally until you do.
